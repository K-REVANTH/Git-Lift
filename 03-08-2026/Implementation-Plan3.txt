=======================================================================
IMPLEMENTATION PLAN 3 — LangGraph Workflow + RAG + Cache
=======================================================================
 
WHAT THIS PHASE DELIVERS
=======================================================================
 
The LangGraph workflow from Phase 2 with the document acquisition layer
replaced by a full RAG pipeline. Documentation is indexed once into
Qdrant. Every query retrieves only the 3 most relevant compressed chunks
(~1,200 tokens) instead of full pages (10,000–40,000 tokens).
Redis semantic cache serves repeat queries at near-zero cost.
 
WHAT CHANGES FROM PHASE 2
=======================================================================
 
  Phase 2 node               Phase 3 replacement
  ────────────────────────   ──────────────────────────────────────
  fetch_source_docs          retrieve_source_docs (Qdrant search)
  fetch_target_docs          retrieve_target_docs (Qdrant search)
  validate_content           validate_retrieval (score thresholds)
  [no expand node]           expand_search (MultiQueryRetriever)
  [no cache check]           check_cache also checks Redis semantic cache
  [no store step]            store_in_memory also writes to Redis cache

  ALL OTHER NODES UNCHANGED:
    classify_feature, analyze_feature, reflect_on_analysis,

NEW COMPONENTS IN PHASE 3
=======================================================================
 
  Qdrant vector database      — stores and searches documentation chunks
  text-embedding-3-small      — converts text to searchable vectors
  EnsembleRetriever           — hybrid BM25 + vector search
  ContextualCompressionRetriever — compresses chunks before LLM call
  MultiQueryRetriever         — expand_search fallback
  Redis SemanticCache         — deduplicates LLM calls across requests
  Offline indexing pipeline   — crawls, splits, embeds, stores docs
  PostgreSQL-backed Store     — upgrades in-memory store from Phase 2
 
DELIVERY TIMELINE
=======================================================================
 
  Week 1-2:  Qdrant setup, indexing pipeline, embedding, metadata
  Week 3:    Hybrid retrieval, contextual compression, score thresholds
  Week 4:    Redis semantic cache, LangGraph Store to PostgreSQL
  Week 5:    Swap fetch nodes for retrieval nodes in existing graph
  Week 6:    End-to-end testing, incremental update scheduler
 
UPGRADE TRIGGERS
=======================================================================
 
  - Cost per analysis is unacceptable at current query volume
  - Same features queried repeatedly with no deduplication benefit
  - HTTP fetch failures from documentation site rate limiting
  - Scaling to bulk analysis of 100+ features per run
  - Terminology mismatches causing wrong pages to be fetched
