=======================================================================
IMPLEMENTATION PLAN 2 — LangGraph Workflow + Direct Document Fetch
=======================================================================
 
WHAT THIS PHASE DELIVERS
=======================================================================
 
The same direct document fetch approach from Phase 1, now orchestrated
by a LangGraph directed graph. This adds retry loops when quality is
insufficient, conditional routing based on confidence scores,
human-in-the-loop review for low-confidence cases, crash recovery via
PostgreSQL checkpoints, and a FastAPI REST API.
 
The document acquisition strategy does NOT change.
Only the orchestration layer is upgraded.
 
WHAT CHANGES FROM PHASE 1
=======================================================================
 
  Phase 1 (LCEL Linear):
    classify → fetch → analyze → guide → compile
 
  Phase 2 (LangGraph):
    check_cache → classify → fetch_source + fetch_target (PARALLEL)
    → validate → analyze → reflect → confidence_routing
    → human_review (if needed) → generate_guide → compile → store

NEW COMPONENTS IN PHASE 2
=======================================================================
 
  LangGraph                  — Directed graph orchestration
  AsyncPostgresSaver         — Checkpoint every node to PostgreSQL
  LangGraph InMemoryStore    — Long-term memory (dev); PostgreSQL (prod)
  LangGraph interrupt()      — Pause graph for human review
  FastAPI                    — REST API to expose graph execution
  reflect_on_analysis chain  — GPT-4o reviews its own output
  check_cache node           — Skip re-analysis if verified result exists
  store_in_memory node       — Save verified results permanently
 
DELIVERY TIMELINE
=======================================================================
 
  Week 1:  LangGraph graph skeleton, state schema, node stubs
  Week 2:  Parallel fetch, validate, confidence routing, reflection
  Week 3:  Human review interrupt, PostgreSQL checkpoints, FastAPI
 
UPGRADE TRIGGERS
=======================================================================
 
  - Phase 1 showing unacceptable analysis quality variance
  - Multiple features need human review with no gate to catch them
  - A migration failure traced back to unreviewed low-confidence analysis
  - Workflow takes long enough that crash recovery is needed

FILE: graph/state.py
-----------------------------------------------------------------------
 
Define MigrationState as a TypedDict with ALL of these fields:
 
  # Input fields
  feature_name: str
  source_platform: str
  target_platform: str
  feature_description: str | None
 
  # Classification fields
  feature_category: str | None
  feature_tags: list[str]
  suggested_gitlab_urls: list[str]
  suggested_github_urls: list[str]
 
  # Fetched document fields
  # Use Annotated with operator.add so parallel nodes merge correctly
  gitlab_docs: Annotated[list[dict], operator.add]
  github_docs: Annotated[list[dict], operator.add]
  content_quality: str | None   # "sufficient" | "failed"
 
  # Analysis fields
  analysis: dict | None         # serialized MigrationAnalysis
  confidence: float
  iterations: int
 
  # Reflection fields
  reflection: dict | None       # serialized ReflectionResult
 
  # Human review fields
  human_feedback: str | None    # "approve" | "reject" | "escalate"
  human_notes: str | None
 
  # Output fields
  migration_guide: dict | None  # serialized MigrationGuide
  final_output: dict | None
  error: str | None
 
  # Metadata fields
  thread_id: str
  started_at: str
  total_llm_calls: int
  cache_hit: bool
 
Use Annotated[list[dict], operator.add] for gitlab_docs and github_docs.
This tells LangGraph to MERGE the lists when parallel nodes both write
to these fields, rather than overwriting one with the other.
