=======================================================================
IMPLEMENTATION PLAN 1 — LangChain Linear Pipeline + Direct Document Fetch
=======================================================================
 
WHAT THIS PHASE DELIVERS
=======================================================================
 
A working command-line tool that accepts a GitLab feature name, fetches
the relevant documentation pages from both platforms directly via HTTP,
and returns a structured JSON analysis with citations.
 
No vector database. No workflow graph. No infrastructure beyond an
OpenAI API key.
 
THE PIPELINE (linear, no loops, no branching):
 
  User Input
      │
      ▼
  classify_feature()        ← GPT-4o-mini: assigns category + likely doc URLs
      │
      ▼
  fetch_source_docs()       ← HTTP GET: docs.gitlab.com pages
  fetch_target_docs()       ← HTTP GET: docs.github.com pages
      │
      ▼
  analyze_feature()         ← GPT-4o: reads both doc sets, structured output
      │
      ▼
  generate_guide()          ← GPT-4o: writes step-by-step migration guide
      │
      ▼
  compile_output()          ← Assembles final validated JSON
      │
      ▼
  Structured JSON Output
 
TECHNOLOGY STACK
=======================================================================
 
  LangChain LCEL       — Linear pipeline composition (prompt | llm | parser)
  GPT-4o               — Core analysis and guide generation
  GPT-4o-mini          — Feature classification (15x cheaper)
  httpx                — Async HTTP document fetching
  BeautifulSoup4       — HTML parsing and content extraction
  Pydantic v2          — Structured, validated output schemas
  LangSmith            — Automatic tracing of every AI call
  Python CLI           — argparse-based command line interface
  pytest               — Unit and integration tests
 
WHAT IS INTENTIONALLY NOT BUILT
=======================================================================
 
  - No vector database (no Qdrant, no embeddings, no indexing)
  - No Redis cache
  - No retry loops
  - No conditional branching based on confidence
  - No human review gate
  - No crash recovery
  - No LangGraph
  - No FastAPI
 
LIMITATIONS AND UPGRADE TRIGGERS
=======================================================================
 
  Limitation              Symptom                    Upgrade Trigger
  ─────────────────────   ────────────────────────   ─────────────────────
  No retry logic          Low-confidence output      Quality varies too much
                          returned to user as-is
  No human review gate    Wrong analyses shipped     High-stakes decisions
                          without validation         need oversight
  No loop capability      Cannot re-fetch if first   Multiple fetch failures
                          fetch fails                per day
  Higher token cost       Full pages = 10K-40K       Cost per analysis is
                          tokens per call            unacceptable
  No caching              Every request refetches    Same features queried
                          and re-analyzes            repeatedly

Define these Pydantic v2 models with

FILE: fetchers/doc_fetcher.py
-----------------------------------------------------------------------
 
Implement an async DocFetcher class.
 
Method: async fetch_page(url: str, platform: str) -> FetchedDocument
  - Use httpx.AsyncClient with timeout=30 seconds
  - Set User-Agent header to "MigrationAssistant/1.0"
  - On HTTP error: return FetchedDocument with fetch_success=False,
    error_message set, content="", word_count=0
  - On success: parse HTML with BeautifulSoup
  - Extract main content using these selectors in order:
    article, main, .content, .markdown-body, body
  - Remove script, style, nav, header, footer tags before extracting text
  - Set word_count = len(content.split())
  - Return FetchedDocument with fetch_success=True
 
Method: async fetch_multiple(urls: list[str], platform: str) -> list[FetchedDocument]
  - Use asyncio.gather to fetch all URLs concurrently
  - Return list of FetchedDocument (including failures)
  - Never raise exceptions. Always return FetchedDocument.
 
Log fetch success/failure at INFO level using Python logging.
Log URL and response size at DEBUG level.
